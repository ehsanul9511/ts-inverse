# Weights-only property measurement on ETT

## Direct inference on recorded client gradients

To evaluate the prepared measurement on client batches, use:

```python
"poison_global_model": True,
"poison_feasibility_only": False,
"attack_mode": "poisoning_assisted_property_inference",
"update_model": False,
"defense_name": "none",
```

Keep your existing poisoning strategy and property/coordinate settings. The
default `attack_mode="gradient_inversion"` retains the reconstruction attack.
`attack_number_of_batches` controls how many recorded client batches are decoded.
The direct route runs even if `num_attack_steps=0`; it does not initialize dummy
data, train an inversion model, or optimize a reconstruction.

The dispatcher selects `gradient_inversion_attack` or
`poisoning_assisted_property_inference`. The latter reads the recorded gradient
by its actual parameter name and decodes using preparation metadata:
`K*g/(2*C)` for constant bias, `(g-beta)/alpha` for fixed projection, and the
arithmetic mean of those decoded values for multiple coordinates. Client inputs
and targets are used only for ground truth and independent analytical identity
checks, not for computing or calibrating estimates. No new backward pass is
needed. Incompatible gradients/model states fail the identity check.

Timestamped `<dataset>_client_property_<timestamp>.md` and `.json` reports are
written to `evaluation_results/` (override `property_inference_output_dir`). They
include each client's true property and estimate, raw gradient entries,
analytical measurements, identity errors, per-window ground truth, and the
preparation/run settings. Multi-coordinate reports include individual and
ensemble errors and signed-error correlations. The constant baseline remains
the one fitted on auxiliary preparation data. No reconstruction files or
reconstruction evaluation are generated by this route.

To run both attacks on each of the same recorded client batches, set
`attack_mode="both"` with the same poisoning/defense settings above and
`num_attack_steps > 0`. Keep the usual inversion settings as well. Direct
inference runs first, followed by gradient inversion from the same model state
and recorded gradients. Normal reconstruction saving/evaluation remains enabled.

The client-property Markdown report includes a separate comparison table with
the original property, direct estimate, property measured in reconstructed
inputs, and each method's absolute error for every batch. A summary compares
property MAE, RMSE and signed bias by batch size. JSON includes these measurements
and `method_comparison`. Both methods use exactly the same property channel,
threshold units and run-duration definition. These are property-estimation
errors, not full time-series reconstruction errors. A missing reconstruction
fails explicitly instead of treating an initialization as a completed attack.

`load_or_train_poisoned_global_model(model, config)` now replaces the previous
masking/multitask approach. It returns the same model, with the same parameters,
state-dictionary keys and forward signature. `poison_global_model=False` retains
the normal preparation path.

`poison_strategy` defaults to `fixed_projection`. Select `constant_bias`
explicitly for the original zero-row/bias intervention. Both single-coordinate
checkpoint metadata/hash conventions are preserved. Checkpoints from the two
strategies cannot be interchanged.

## Fixed projection option

Use the existing dataset/property/preparation options together with:

```python
"poison_global_model": True,
"poison_strategy": "fixed_projection",
"poison_target_channel": "HUFL",
"poison_gradient_scale": 1.0,   # alpha: finite, nonzero
"poison_gradient_offset": 0.0,  # beta: finite
"poison_train_epochs": 10,
"poison_max_relative_weight_change": None,  # optionally 0.05
```

This strategy preserves the entire starting projection, after loading an optional
`poison_base_checkpoint_path`. It skips feature warm-up and trains only upstream
parameters with the per-window measurement
`s = ((2/K) * mean_t((forecast_k - target_k) * h_j) - beta) / alpha`.
Both factors retain their preparation gradients. The actual scalar gradient is
decoded as `(g - beta) / alpha`; defaults make the estimate equal to `g` directly.
`poison_measurement_C` is unused in this strategy. Effective feature epochs are zero.

The optional budget `rho` bounds each optimized upstream tensor's displacement
to `rho * max(original_tensor.norm(), 1e-12)`, projecting after every Adam step.
References remain fixed throughout preparation. Zero permits no weight changes;
`None` imposes no constraint. The output projection is frozen independently.

The checkpoint includes an exact copy of the original projection, verified on
reload. Metadata includes the strategy, decoding constants, effective stages and
budget. Held-out validation checks both the raw scalar-gradient identity and the
decoded measurement identity, using the existing batches and reports.

For the original strategy, use `"poison_strategy": "constant_bias"`
and `"poison_measurement_C": 10.0`; decoding remains `K*g/(2*C)`.

## Several coordinates for the same property

For `fixed_projection`, optionally supply an ordered list. All measurements
estimate the single property configured by `poison_target_channel` and its
threshold, units and minimum duration. Output rows are measurement locations,
not additional property labels.

```python
# Existing single-coordinate configuration:
"poison_measurement_channel": "HUFL",
"poison_hidden_coordinate": 0,

# Alternatively, four coordinates from one output row:
"poison_gradient_coordinates": [
    {"channel": "HUFL", "hidden_coordinate": j} for j in [0, 8, 16, 24]
],
"poison_ensemble_loss_weight": 0.5,
```

Or use several output rows (M mode):

```python
"poison_gradient_coordinates": [
    {"channel": "HUFL", "hidden_coordinate": 0},
    {"channel": "HUFL", "hidden_coordinate": 8},
    {"channel": "MUFL", "hidden_coordinate": 16},
    {"channel": "LUFL", "hidden_coordinate": 24},
],
```

The list takes precedence over singular measurement settings. It must be
nonempty, with unique resolved row/hidden pairs. MS allows only the last raw
output row; S allows only its sole channel. `constant_bias` rejects this option.

Each coordinate decodes as `(gradient - beta) / alpha`; the final estimate is
their arithmetic mean. Shared scale and offset retain defaults 1 and 0. Training
uses `(1-lambda)*individual_MSE + lambda*ensemble_MSE`, with means over
coordinates, `lambda=0.5` by default, and `0 <= lambda < 1`. A one-element list
uses the unchanged scalar loss and checkpoint identity. Each minibatch needs
one model forward and each held-out batch needs one client backward pass.

Multi-coordinate reports retain all individual estimates and raw gradient
scalars. Main batch errors describe the ensemble; supplementary tables compare
each coordinate's MAE, RMSE and signed bias with the ensemble. Pairwise
correlations use signed estimation errors, with undefined/null entries for
constant errors or fewer than two observations. Averaging is not assumed to
improve accuracy, and no choices are fitted on the holdout.

Genuine multi-coordinate checkpoints have a distinct method identifier. Ordered
coordinates, aggregation rule and ensemble loss weight join the existing hashed
metadata. They cannot reuse single-coordinate prepared checkpoints. The complete
projection reference and optional upstream weight-change constraint are retained.

This experiment currently supports the vanilla Transformer's existing
`decoder.projection` layer. It rejects iTransformer and any post-projection
normalization or transformation incompatible with the measurement identity.
Forecasting utility is not preserved by this experiment.

## Auxiliary-only run

The notebook `notebooks/ts_inverse_har.py` is configured to run this check and stop
before client-gradient collection or reconstruction:

```python
"poison_global_model": [True],
"poison_strategy": "constant_bias",
"poison_feasibility_only": True,
"poison_target_channel": "HUFL",
"poison_auxiliary_split": "test",  # alternatively "val"
"poison_feature_epochs": 10,
"poison_train_epochs": 10,
"poison_measurement_C": 10.0,
"poison_hidden_coordinate": 0,
"poison_holdout_fraction": 0.2,
"poison_validation_batch_sizes": [[1, 8, 32]],
"poison_validation_batches": 8,
"poison_property_units": "standardized",
"poison_property_threshold": 0.5,
"poison_property_duration": 1,
```

The nested batch-size list is required by the notebook's grid search. A direct
function call takes `[1, 8, 32]`. Batch sizes exceeding the holdout are skipped.
`poison_train_batch_size` and `poison_train_learning_rate` default to the existing
`model_train_*` settings. `poison_feasibility_tolerance` defaults to 0.05, measured
in property-fraction units (five percentage points).

## Measurement and preparation

Let `c` be the property input channel, `k` the measurement output channel, and `j`
the selected hidden coordinate. Preparation fixes the existing projection row
`W[k, :] = 0` and bias `b[k] = C > 0`. It freezes the entire final projection and
trains the existing upstream parameters in eval mode, matching the deterministic
client gradient calculation. No new head, parameter, buffer or module is added.

1. Feature warm-up fits `mean_t h[t,j]` to the exact per-window property.
2. Measurement fine-tuning fits `mean_t ((1 - y[t,k]/C) * h[t,j])` to that property.
3. Held-out validation computes the actual ordinary mean-MSE backward pass,
   reads `decoder.projection.weight.grad[k,j]`, and estimates the batch property
   as `K * grad / (2*C)`, where `K` is the number of output channels in the loss.

The function checks this last quantity against the analytic finite-C contribution
numerically. Agreement verifies the implementation of the identity; prediction
accuracy against the true property separately tests whether preparation worked.
The projection is restored to its original trainability before validation and
return. Validation never takes an optimizer step, and gradients are cleared before
return. The row remains exactly zero and the bias remains C.

`poison_target_channel` accepts a name or zero-based input-channel index.
`poison_measurement_channel` defaults to that channel for M/S and the last output
channel for MS. MS can measure an arbitrary input-channel property, but the
measurement output must be the last channel included in the client loss. The
actual parameter name and coordinate are saved in the config; no last-gradient
assumption is used.

The property reuses `pi_eval.property_inference.run_fractions`: count all timesteps
in maximal runs strictly above the threshold whose length is at least the duration,
then divide by the input-window length. Short runs are excluded. Standardized
thresholds apply directly to scaled input; physical thresholds first undo the
training scaler for the selected channel. Standardized thresholds on unscaled
data are rejected.

## Holdout and reports

Within the chosen auxiliary split, preparation uses the earlier temporal block and
validation the later block. Initial lookback windows and windows crossing the
boundary are excluded so the two partitions share neither input nor target
timesteps. Both blocks may contain internally overlapping windows; batch-size
results are therefore descriptive, not independent-sample confidence intervals.

Validation uses seeded, shuffled full batches and compares its estimates against
a constant fitted only to preparation-property labels. It reports MAE, RMSE,
bias, true-property and estimate variation, their correlation, baseline errors, numerical identity error and
whether MAE beats the baseline and meets the configured tolerance. Estimates are
not clipped. Low error on nearly constant batch properties alone does not establish
informative leakage. Holdout results do not select epochs, C or checkpoints.
If CUDA reduced-precision matrix multiplication fails the numerical identity
check, retry with `torch.set_float32_matmul_precision('highest')`.

Console summaries and JSON/Markdown reports are produced on every call, including
checkpoint reloads. Reports live in `evaluation_results/` by default; override
with `poison_feasibility_output_dir`. JSON includes per-batch gradient values,
true properties, estimates and feature/target-correction diagnostics.
Markdown starts with one row per held-out batch, showing its original property,
gradient estimate, signed error, absolute error and observed gradient scalar.
The same comparisons are printed during validation. Aggregate diagnostics follow
these tables. `poison_validation_batches` defaults to eight batches per batch
size; it is distinct from the number of windows in each batch.

## Checkpoints and later attacks

Compatible complete checkpoints skip preparation but rerun holdout validation.
The default path is `models/poisoned_global/<dataset>_weights_only_<hash>.pt`.
`poison_checkpoint_path` selects an explicit file. Metadata validates architecture,
parameter names, channel ordering, preprocessing, property settings, source file,
temporal partitions and training settings. Incompatible or legacy poisoning
checkpoints fail clearly. Use a new path or explicitly set
`poison_force_retrain=True` to overwrite one.

By default the incoming initialized model is prepared directly; clean forecasting
pretraining is not needed for this utility-unconstrained experiment. Optionally
`poison_base_checkpoint_path` loads a clean state dict before preparation. That
checkpoint must not have been trained on the held-out auxiliary block; the code
cannot establish its training-data provenance.

To later resume the full attack pipeline, set `poison_feasibility_only=False`,
`update_model=False` and `defense_name="none"`. The measurement assumes raw gradients
at the fixed model, not multiple local updates or transformed gradients. An
auxiliary-only run explicitly reports that configured client defenses are not
applied. Learned inversion/cache loading and one-shot target recovery are disabled
for this mode. This change does not implement target-client property decoding.
